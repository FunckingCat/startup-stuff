# Дизайн: LLM-вики по стартапам

Дата: 2026-08-19
Статус: утверждён, готов к плану реализации

## 1. Контекст и задача

Персональная база знаний по теме «как делать стартапы»: строить, управлять, искать
идеи. Строится по паттерну LLM Wiki (Andrej Karpathy, апрель 2026): знание не
извлекается заново на каждый запрос, а компилируется один раз при приёме источника
и поддерживается в актуальном состоянии.

Владелец репозитория — David Zh. Репозиторий `startup-stuff`, на момент дизайна пуст.
Поверх репозитория открывается Obsidian как вольт.

### Требования владельца

| Требование | Источник | Следствие для дизайна |
|---|---|---|
| Компиляция изученных источников с перекрёстными связями | короткая память, нужна внешняя опора | граф — интерфейс первого класса, а не побочный эффект |
| Источники — текст или ссылка, чаще транскрипции видео и статьи | поток ввода | агент сам сохраняет raw, Web Clipper опционален |
| Последовательный приём, полная автономность | режим работы | человек читает отчёт постфактум, откат через git |
| Встроенные процессы фильтрации и компрессии | явное требование | фильтр из четырёх структурных тестов, две ступени компрессии |
| Язык вики — русский | явное требование | страницы и имена файлов по-русски, термины в оригинале |
| Стадия плавает (учусь / ищу идею / строю) | ответ на вопрос о позиции | стадия не зашивается в схему, выносится в `me/context.md` |
| Запросы адресованы проблемам, не источникам | ответ о выходах | хребет вики — страницы-проблемы |
| Основной вход — блуждание по графу | ответ о выходах | сирота и хаб-клубок трактуются как дефекты |

### Что осознанно не делается

- Не первичный источник для юридических и финансовых решений: компрессия LLM запекает
  ошибки в «факты», и они расползаются по связанным страницам.
- Никаких embeddings и RAG-инфраструктуры на старте. Плоский индекс достаточен.
- Нет отдельной системы карточек для повторения: повторение идёт поверх графа.

## 2. Выбранная архитектура

Вариант «проблемный атлас»: хребет — страницы-проблемы, вокруг — концепты, люди и
тонкие страницы источников. Взято из альтернатив: структурированный блок тезиса с
атрибуцией и условиями применимости (из тезис-атомарного варианта, но блоками внутри
страниц, а не отдельными файлами) и тонкие страницы источников ради цитируемости
(из классического варианта Карпаты).

Отвергнуты: тезис-атомарная база (тысячи микрофайлов превращают граф в клубок,
нечитаемый глазами — а именно глазами он и будет читаться) и классический
источнико-центричный вариант (ось источников — ровно та, которая владельцу не нужна).

### Три слоя и владение

| Слой | Владелец | Правило |
|---|---|---|
| `raw/` | человек | иммутабелен; агент читает, но никогда не правит |
| `wiki/` | агент | человек читает, агент пишет и поддерживает |
| `me/` | человек | агент читает и предлагает правки в `/digest`, но не пишет |
| `CLAUDE.md` | совместно | схема со-эволюционирует по мере обнаружения несрабатывающих правил |

### Структура репозитория

```
CLAUDE.md              схема: контракт агента
index.md               каталог страниц вики
log.md                 append-only хронология
me/
  context.md           стадия, проект, открытые вопросы; правит человек
raw/
  ГГГГ-ММ-ДД-slug.md   источник как есть, иммутабелен
  assets/              вложения
wiki/
  problems/            хребет
  concepts/            термины, фреймворки, метрики
  people/              авторы и их сквозные позиции
  sources/             тонкие страницы происхождения
```

Имена файлов — русские kebab-case (`wiki/problems/первые-10-клиентов.md`). В graph view
подписи узлов берутся из имён файлов, а граф — основной интерфейс.

## 3. Типы страниц

**Проблема.** Названа как вопрос в момент столкновения: `когда-убивать-идею`,
`первые-10-клиентов`, `как-отличить-живую-боль`. Содержит блоки тезисов из разных
источников, сгруппированные по позициям. Основная точка входа из графа.

**Концепт.** Термин, фреймворк, метрика: `pmf`, `icp`, `mom-test`. Существует ради
связности: проблемы связываются друг с другом через концепты, а не напрямую.

**Человек.** Автор и его сквозная позиция: во что верит, на каком опыте это основано,
где систематически расходится с другими. Заводится только со второго источника от
этого человека, иначе плодим сирот.

**Источник.** Тонкая страница происхождения: метаданные, три строки о чём, куда ушли
тезисы, что отброшено и почему. Одновременно артефакт отчёта фильтра. Исключается из
графа фильтром `-path:wiki/sources`.

**Антипаттерн** отдельного типа не имеет: это блок тезиса с пометкой внутри страницы
проблемы. Повышается до собственной страницы только при появлении в трёх и более
независимых источниках.

Фронтматтер всех страниц: `тип`, `обновлено`, `источников`. Страница-заготовка несёт
дополнительно `статус: открытая`.

### Блок тезиса — атомарная единица

```markdown
- **Не нанимай продажника, пока основатель сам не закрыл ~30 сделок.**
  — *Джейсон Лемкин*, [[2026-08-19-saastr-first-sales-hire]]
  Условия: B2B SaaS, чек $10k+, до PMF
  Спорит с: [[когда-делегировать-продажи]]
```

Обязательны три поля: утверждение, кто и откуда, условия применимости. Поле
«Спорит с» — по факту наличия конфликта.

Обязательность условий — ключевое решение дизайна. Стартап-советы верны в своём
контексте и вредны вне его, а стадия владельца плавает. Тезис без записанных условий
через полгода будет вводить в заблуждение.

## 4. Процессы

### 4.1 Ингест — восемь шагов

1. **Приём.** Ссылка выкачивается, текст сохраняется как есть — в
   `raw/ГГГГ-ММ-ДД-slug.md` с фронтматтером (url, автор, дата, тип, добавлено).
   После записи файл иммутабелен.
2. **Чтение.** Источник целиком, `me/context.md`, `index.md`. Без контекста фильтр не
   знает, что релевантно; без индекса — что уже есть.
3. **Извлечение.** Все кандидатные утверждения без оценки. На часовой транскрипции
   обычно 30–50.
4. **Фильтр.** Четыре теста по порядку, первый сработавший убивает тезис (см. 4.2).
5. **Компрессия источника.** Выжившее — одно предложение, утвердительно, без имён
   брендов ради красоты. Жёсткой квоты нет. Контрольное правило: прошло больше
   12 тезисов — перепроверить фильтр, он был мягок. Норма с хорошей часовой лекции 5–9.
6. **Интеграция.** Блоки в страницы проблем; создание недостающих проблем и концептов;
   обновление страниц людей; перекрёстные ссылки. Противоречие даёт **двустороннюю**
   ссылку «Спорит с»: односторонняя находит только одну сторону спора.
7. **Гигиена.** Правило дробления; проверка, что ни одна новая страница не сирота.
8. **Бухгалтерия.** Страница источника, `index.md`, строка в `log.md` формата
   `## [2026-08-19] ingest | Название`.

Затем коммит: `[STARTUP-WIKI][Ingest][Название источника]`.

### 4.2 Фильтр

Тесты применяются по порядку, первый сработавший прекращает обработку тезиса.

1. **Банальность.** Тест на фальсифицируемость: существует ли вменяемая
   противоположная позиция? «Надо любить клиента», «важно быстро итерироваться» —
   противоположной позиции нет, информации ноль. Убить.
2. **Нет условий применимости.** Не выписываются стадия, тип бизнеса или рынок. Убить.
3. **Дубль.** То же самое уже есть — не новый блок, а добавление источника к
   существующему блоку. Формально слияние, но в отчёте считается отдельно:
   повторяемость сама по себе сигнал, что утверждение устоялось.
4. **Неприкрепляемость.** Не ложится ни на одну существующую проблему и не тянет на
   новую проблему или концепт. Убить.

**Ошибка выжившего** — отдельное правило поверх тестов. История одной компании,
поданная как правило, не отбраковывается, но не может стать самостоятельным тезисом:
допускается только как иллюстрация к уже существующему. Отсекает главный жанровый
мусор стартап-контента, не теряя хороших историй.

Отброшенное не сохраняется нигде, кроме сводных чисел в отчёте и `log.md`.

### 4.3 Компрессия страниц

Работает при каждом ингесте, держит вики читаемой на дистанции.

- **Дробление.** Страница проблемы перевалила за 12 блоков либо содержит два явно
  разных подвопроса — делится на подпроблемы, на родителе остаётся оглавление со
  ссылками.
- **Схлопывание.** Четыре и более блоков утверждают одно и то же — сливаются в один
  консенсусный тезис со списком источников. Так в вики проявляется устоявшееся,
  в отличие от единичных мнений.

### 4.4 Отчёт

```
Источник: <название> — <автор>
Взято N из M. Отброшено: X банальностей, Y дублей, Z без условий.
Новое:
  • <тезис одной строкой> → [[проблема]]
Затронуто K страниц. Создано: [[...]], [[...]].
Противоречие: <A> против <B> — <в чём суть расхождения>.
Пробел: <вопрос, на который в вики нет ответа>
```

В отчёт идут сами тезисы одной строкой, а не «обновлено 9 страниц». Чтение отчёта
работает как микро-повторение и компенсирует полную автономность ингеста.

### 4.5 Запрос

Обычным разговором, без команды. Сначала `index.md`, затем нужные страницы; ответ со
ссылками на конкретные блоки. Два правила:

- Ценный ответ возвращается в вики новой страницей — иначе компаундится только чужой
  контент, а собственные выводы растворяются в истории чата.
- Вопрос, не легший ни на одну проблему, заводит страницу-заготовку со статусом
  `открытая`: будущие источники начнут её заполнять, а в графе видно, где дыра.

### 4.6 `/lint`

Раз в пару недель. Чеклист: неотмеченные противоречия; устаревшие утверждения;
сироты; концепты, упомянутые без собственной страницы; страницы за порогом дробления;
дыры в покрытии. На выходе — список правок и предложения, что почитать дальше.

### 4.7 `/digest`

Раз в неделю или по команде. Не пересказ: 3–5 тезисов за период, плюс 1–2 старых,
связанных с ними по графу, плюс один вопрос на самопроверку. Перемешивание нового со
старым даёт удержание, сплошной пересказ — нет.

Здесь же агент предлагает правки `me/context.md`, если наблюдаемые интересы разошлись
с записанными. Сам файл не правит.

## 5. Разрешение противоречий

Противоречия фиксируются, а не устраняются. Запрещено выбирать «правильную» сторону
или усреднять: у двух противоречащих советов почти всегда разные условия
применимости, и разница условий и есть знание.

Процедура: сравнить условия обоих тезисов. Условия различаются — переписать оба
точнее, конфликт исчезает. Условия совпадают, выводы разные — настоящий спор,
остаётся с двусторонними ссылками и пометкой.

## 6. Гигиена графа

- Сирота (нет входящих ссылок) — дефект; лечится при ингесте и линте.
- Страницы источников исключены из графа фильтром `-path:wiki/sources`.
- Связь двух проблем идёт через концепт, а не прямой ссылкой: прямые связи
  превращают граф в клубок.
- Висячих ссылок не заводим: ссылка ставится на существующую или тут же создаваемую
  страницу.

## 7. Масштабирование

Плоский `index.md` достаточен примерно до 150–200 страниц. Дальше, по факту боли, а не
заранее:

1. Иерархический индекс по доменам (поиск идей / продукт / продажи / найм / деньги).
2. Локальный поиск qmd (гибрид BM25 и векторов, офлайн, CLI и MCP).

Триггер перехода: агент промахивается мимо нужных страниц либо `index.md` перестаёт
влезать в разумный контекст.

## 8. Git и Obsidian

Коммит после каждого ингеста по шаблону `[STARTUP-WIKI][Ingest][Название]`. Это делает
полную автономность безопасной: неудачный ингест откатывается одной командой.

Obsidian: вложения в `raw/assets/`, фильтр графа `-path:wiki/sources`, Web Clipper для
статей. Dataview — только если позже понадобятся таблицы.

## 9. Язык

Страницы по-русски. Термины остаются в оригинале с русским пояснением при первом
употреблении: PMF, ICP, churn, runway. Перевод терминов сделал бы вики несовместимой
с читаемыми источниками.

## 10. Состав `CLAUDE.md`

Порядок разделов схемы: назначение и читатель; три слоя и владение; типология страниц
с шаблонами; конвенции именования и связывания; конвейер ингеста; правила фильтра;
правила компрессии; формат отчёта; правила запроса; разрешение противоречий; чеклист
линта; формат дайджеста; язык и терминология. Всего 13 разделов.

Схема со-эволюционирует: когда правило не срабатывает, правится схема, а не разовое
поведение — иначе поведение не сохранится между сессиями.

## 11. Критерии готовности

1. Структура каталогов создана, `CLAUDE.md` содержит все 13 разделов.
2. `me/context.md` заполнен владельцем.
3. `/ingest`, `/lint`, `/digest` определены файлами в `.claude/commands/`.
4. Прогон на реальном источнике: raw сохранён, отчёт соответствует формату из 4.4,
   каждый новый тезис несёт условия применимости, ни одна созданная страница не
   сирота, `index.md` и `log.md` обновлены, коммит по шаблону.
5. Прогон на втором источнике той же темы: сработали дубль-слияние либо фиксация
   противоречия с двусторонними ссылками.
